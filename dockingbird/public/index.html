01 / COORDINATION

Parallel work.
Shared direction.

Let agents build, review, and test together while you focus on the decisions that need you.

01

Give every agent its own space.

Each agent works in an isolated container and private clone. Path claims and checked submissions protect shared work as commits come together.

02

Keep handoffs moving.

Agents send questions, reports, and artifacts through a shared message bus. Context reaches the right session without you relaying it between terminals.

03

Stay close to the work.

See what is working, waiting, or asking for your input. Open a session when you need the detail, then let the team get back to it.

A FEW DETAILS

Before you take flight.

Do I keep using Claude Code and Codex?+

Yes. Dockingbird coordinates the coding agents you already use. Each runs in its own container with its own workspace, while Dockingbird manages communication and shared work.

Can I bring my own instructions and tools?+

Yes. Reusable configurations can select the harness and model settings, supply role instructions and environment variables, and load trusted repository settings. Your project’s agent files, hooks, and mise toolchain can shape how agents work. Hook support depends on the harness.

Can the agents run on different machines?+

Dockingbird can coordinate local and remote hosts. Its fleet scheduler queues work, considers CPU and memory availability, and provides controls for priority, holds, pause, resume, and host draining.
